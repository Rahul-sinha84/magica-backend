Every error has the same shape. `error` is safe to show to a user; `code` is stable, so branch on it.

```json Error
{
  "error": "That API key isn't valid. Check it, or create a new one.",
  "code": "UNAUTHORIZED",
  "traceId": "5787578d-cec2-41c2-b100-9dabf18a95c8"
}
```

`traceId` is also sent as the `x-trace-id` header of every response. Quote it when asking for help.

## HTTP errors

| Code | Status | Meaning |
| --- | --- | --- |
| `VALIDATION_FAILED` | 400 | The request isn't valid. `error` names the field and the problem; `details.fields` lists every field that failed. |
| `UNAUTHORIZED` | 401 | No valid API key or session token. Check the key; a revoked or expired key is refused the same way as an unknown one. |
| `INSUFFICIENT_CREDITS` | 402 | Not enough credits for this. Nothing was charged. |
| `NOT_FOUND` | 404 | It doesn't exist, or it isn't yours (the API never says which). |
| `API_KEY_LIMIT_REACHED` | 409 | You already have the most active API keys allowed (10). Revoke one to create another. |
| `IDEMPOTENCY_CONFLICT` | 409 | The `Idempotency-Key` was already used for a different request, or the first request with it is still being handled. |
| `RUN_ACTIVE` | 409 | The chat already has a run in progress. Wait for it to end (or stop it), then send again. |
| `RUN_NOT_RETRYABLE` | 409 | Only a chat's latest turn can be retried, and only if it failed or was stopped (the app's retry). |
| `PAYLOAD_TOO_LARGE` | 413 | The request body is over 1 MB. |
| `RATE_LIMITED` | 429 | A limit was reached: your key's per-minute or daily limit, or the allowance for starting work. Wait for `Retry-After` seconds; `details` says which limit. |
| `UPLOAD_LIMIT_REACHED` | 429 | The month's upload allowance is used up (the app's uploads). It resets on the 1st. |
| `INTERNAL_ERROR` | 500 | Something went wrong on our side. Try again, and quote the `traceId` if it keeps happening. |
| `SERVICE_UNAVAILABLE` | 503 | Something the request needs is unavailable right now (for example the free model's daily limit, or a service that didn't answer). Try again later; `details` may say why. |

## Why a run failed

A run that fails is still answered `200` by `GET /v1/runs/{runId}`: its `status` is `failed` and `error` says why. The `agent.failed` webhook carries the same code (as `data.code`) and message.

| Code | Meaning |
| --- | --- |
| `MODEL_RATE_LIMITED` | The free model is busy right now. Please try again in a moment. |
| `MODEL_DAILY_LIMIT` | The free model's daily limit is reached. It resets at 00:00 UTC. |
| `MODEL_UNAVAILABLE` | The assistant is unavailable right now. Please try again shortly. |
| `MODEL_EMPTY` | The assistant didn't return an answer. Please try again. |
| `MODEL_INTERRUPTED` | The response was interrupted. What was written so far is kept. |
| `MODEL_REJECTED` | The assistant couldn't process this conversation. |
| `MODEL_CONFIG` | The assistant isn't available right now. |
| `WAITPOINT_EXPIRED` | Nobody answered the plan or spend approval within 30 minutes. Send a new message to continue. |
| `INSUFFICIENT_CREDITS` | The credits ran out during the run. What it finished is kept. |
| `AGENT_MAX_STEPS` | The agent reached its limit of steps (model calls) before finishing. What it did so far is kept. |
| `AGENT_TIMEOUT` | The run took longer than its time limit. |
| `AGENT_CRASHED` | The worker running it stopped unexpectedly. |
| `AGENT_FAILED` | The worker reported the run as failed. |
| `AGENT_ERROR` | The agent ran into an unexpected problem. |
| `AGENT_NOT_STARTED` | No worker could start the run (the service may be down). |
| `AGENT_EXPIRED` | The run waited in the queue too long and was dropped. |
| `DISPATCH_LOST` | The run was never handed to a worker. |
| `RESULT_LOST` | The answer was generated but couldn't be saved. |
| `CONTEXT_EMPTY` | The message the run was answering couldn't be found. |
